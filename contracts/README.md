# Pinned NevaBridge contract

`nevabridge-v1.yaml` is the OpenAPI source of the NevaBridge Tenant Integration API. The clients in
this repository treat it as generated input, not as a source file. OpenAPI Generator reads it, and
every published wire type comes from it.

The NevaBridge service repository owns the YAML source. **Do not edit this file by hand.** Refresh
it only from an upstream commit someone has reviewed, and update `pin.json` in the same change.
Then run the full gate. It regenerates every client and shows the resulting diff.

`pin.json` records the commit the file came from, its path in the service repository, and its
SHA-256. `bun run contract:verify` recomputes that checksum and fails when the vendored bytes and
the recorded pin disagree. This check is separate from the generation drift check on purpose.
Generation only proves that the committed client matches whatever is vendored here, so a hand-edited
contract would regenerate cleanly and still be wrong.

## What the local check does and does not prove

`contract:verify` proves the vendored bytes have not changed since someone pinned them. It cannot
prove that the bytes came from the recorded commit. The checksum and the commit sit side by side in
the same file, so a refresh that updates both consistently passes no matter what it claims.

The service repository settles that question, because only it holds the history. Its
`contract:consumers` check hashes the contract as it was at each consumer's recorded commit. The
check fails when that hash differs from the checksum the consumer recorded. A refresh here is
complete only after the service repository updates its entry for this consumer and its gate
confirms the pair.

## Refreshing

1. Take the new `api/openapi/nevabridge-v1.yaml` from a reviewed upstream commit.
2. Replace this directory's copy with it verbatim. Do not reformat it or add a trailing newline.
3. Set `commit` and `sha256` in `pin.json` to the upstream commit and the new file's checksum.
4. Run `bun run check`. Regeneration produces the client diff. Review it like any other code.
