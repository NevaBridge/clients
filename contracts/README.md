# Pinned NevaBridge contract

`nevabridge-v1.yaml` is the OpenAPI source of the NevaBridge Tenant Integration API. It is
generated input to the clients in this repository, not a source file: OpenAPI Generator reads it,
and every published wire type is derived from it.

The YAML source is owned by the NevaBridge service repository. **Do not edit this file by hand.**
Refresh it only from an explicitly reviewed upstream commit, update `pin.json` in the same change,
and run the full gate afterwards, which will regenerate every client and show the resulting diff.

`pin.json` records the commit the file was taken from, its path in the service repository,
and its SHA-256. `bun run contract:verify` recomputes that checksum and fails when the vendored
bytes and the recorded pin disagree. That check is deliberately separate from the generation drift
check: generation only proves the committed client matches whatever is vendored here, so a
hand-edited contract would regenerate cleanly and still be wrong.

## Refreshing

1. Take the new `api/openapi/nevabridge-v1.yaml` from a reviewed upstream commit.
2. Replace this directory's copy with it verbatim, with no reformatting and no added newline.
3. Set `commit` and `sha256` in `pin.json` to the upstream commit and the new file's checksum.
4. Run `bun run check`. Regeneration will produce the client diff; review it as normal code.
